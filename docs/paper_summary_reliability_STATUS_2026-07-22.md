# 文章总结可靠性加固状态（2026-07-22）

项目：`/mnt/d/claude`（Windows：`D:\claude`）
范围：学术语言工作台的任务恢复、批量并发、总结检查点、DOCX 正文边界、完整性与语言审计。
数据纪律：所有原件保持不变；检查点只追加，版面修复先写入 `tmp/` 并渲染确认后再原子替换正式阅读副本。
真实任务仅在用户要求重试后续跑；Hsu 修复前的 PDF 另存于 `tmp/pdfs/final_hsu/`，可回退核对。

## 本次改动

1. **恢复与队列**
   - 新任务 manifest 升级为 schema 2。
   - 服务启动时把遗留的 `queued/running` 任务原子标记为 `interrupted`，保留原件与检查点，不自动占用 GPU。
   - `ThreadPoolExecutor` 固定 worker 队列取代“每个文件一个线程”；默认并发 1，可用
     `TRANSLATION_MAX_CONCURRENT_JOBS=1..4` 显式调整。
2. **检查点哈希**
   - `summary.jsonl` 升级为 schema 2；每个小结保存对应源单元 SHA-256。
   - 哈希覆盖标题、正文、目标语言、领域、术语表与提示版本；旧版无哈希记录安全失效并重算。
   - 每次运行先核对本机原文件与 manifest 的输入 SHA-256，不一致时硬失败。
3. **DOCX 正文边界**
   - 总结只使用 `word/document.xml`；页眉、页脚、批注、脚注和尾注不进入模型总结输入。
   - 翻译路径保持原行为，仍可按既有规则处理这些 OOXML part。
4. **完整性与语言审计**
   - 仅标题、无正文的章节不再交给模型推断。
   - 单个超长段落也会拆到安全预算内；超过 400 节时明确失败，不再静默截断。
   - 全文 reduce 可递归压缩，最终必须返回四个非空 JSON 字段，再由本机按简中、繁中或英文确定性渲染标题。
   - map 完成后再次核对预期单元数；缺少任一正文单元或全文摘要为空都会硬失败，不生成“已完成”的残缺结果。
   - 输出记录 CJK/Latin 目标文字占比与 `pass/warning/insufficient_text` 状态。该启发式只发出可见警告，避免因缩写、英文构念名或引文误删仍可人工核对的结果。
   - 领域提示与匹配术语表进入 map/reduce 提示。
   - manifest 新增总结参数、`summary_sha256`、`summary_bytes`；总结 Markdown 写入覆盖审计和排除项。
   - 翻译任务清单、详情、配置与文本查看响应统一使用 `Cache-Control: no-store, private`。

## 运行中故障跟进：单元级校验修复

实际批量任务暴露出两种可重复的单元级模型错误：一个 834 字 PDF 单元连续遗漏 9 个保护占位符中的首个，
另一个 49 字单元返回完整内容但缺少句末标点。修复保持原硬校验，不接受损坏输出：

- 多单元结构失败仍先二分到单元；单个单元失败后使用不同 seed 和明确修复提示自动重请求。
- 若模型仍遗漏保护占位符，仅把锚点之间的普通文本逐片段送入模型；数字、引用、链接和术语值完全由本机按原顺序精确插回。
- 片段回退提示不再向模型描述 `KEEP` 协议，并明确禁止生成未知保护标记；未知标记仍是硬失败，不能混入成品。
- manifest 审计新增 `validation_retries_used` 和 `protected_anchor_fallbacks_used`，完成后页面会显示实际修复次数。
- 新增 PDF 单元兼容、本机锚点恢复及 watchdog 活跃任务保护回归。
- 两个真实失败单元分别验证通过：句末截断单元自动重请求 1 次；保护占位符单元使用本机锚点恢复 1 次。
- 最终真实续跑中，Hsu 从 39/220 检查点恢复并越过原固定失败点，完成 220/220；实际使用 6 次单元校验重试与 2 次本机保护锚点回填。
- Makridi 按新版段落边界恢复 169/169 个检查点，无需重复模型翻译，并完成 PDF 回写及总结。
- 原始“中断”对应 watchdog 在任务运行期间两次健康超时后重启服务；当时还并行存在两个相同 watchdog。
  现已收敛为一个实例。watchdog 会在 manifest 的运行进度 10 分钟内仍有更新时延后重启；超过 10 分钟无更新时仍按原规则恢复真正失联的服务。

## 运行中故障跟进：PDF 段落边界与版面回写

续跑越过首个固定失败点后，真实 PDF 又暴露出两个确定性问题：表头 `Std. Err.` 的缩写句点被误当成正文句末，
以及小字号回归表拉低当页“正文字号”后，9.96pt 正文被误判为标题并逐行翻译。后者使模型失去句子上下文，也导致单行回写框溢出。

- 句末校验仍对完整句、疑问句和感叹句生效，仅对有限、明确的学术/表格缩写豁免。
- PDF 抽取先用开头页正文推断文档级字号，当页确实出现该字号的连续正文时优先使用，避免表格和尾注污染边界。
- 使用带 `Table`/`Figure` 标签的混合文本/线条检测补足无网格表格与图；标签不存在时不采信，避免把首页摘要误当表格。
- 软连字换行在本机重组；页眉页脚留原文；首页窄元数据栏会避让右侧摘要矩形，不再扩展到半页宽。
- 新边界依旧用源文本 SHA-256 恢复检查点；旧逐行单元与新段落哈希不同，不会被静默复用。
- 两份真实 PDF 的零模型原文回填通过：页数、页面尺寸、图片内容/位置、链接数和无效字符计数不变；最小文字缩放约 0.85，无低于 0.72 的区域。
- 真实中文回写进一步发现 Unicode 上标数字在 PDF 字体文本层中会映射为 NUL；现改为用 HTML `sup` 渲染普通数字。
  缓存译文的本机重写复验中，新增 NUL 从 23 降为 0，最小缩放 0.866，低缩放区域为 0。
- 进程所有权写入 `worker_pid`；不同进程导入 `server.py` 时，只要真实 worker 仍存活，不得把其任务重分类为中断。队列提交失败也会清理所有权并留为可重试。
- 首页宽栏中仅缩进约一个小字号字符的续行现在继承前一宽栏。Hsu 的 `University of / Pennsylvania.` 不再被拆到左栏并与资助信息叠写；仅重译受影响的 2 个片段，旧成品已保留。
- 最终全项目回归为 226 项通过、0 失败；新服务 PID 75056，单 worker 配置保持为 1，Iverson 的 Qwen 健康可用。
- 最后一次版面改动后的首轮全回归曾出现 1 次仅总结临时任务的瞬时失败；该用例单独连续 2 次通过，随后完整 226 项连续 6 轮通过，未再复现。
