# 城投债候选发行额、现金流与付息公告状态（2026-08-05）

## 本轮结论

中国货币网公开债券查询可以提供单只债券的计划发行量、实际发行量、到期日、起息日、
付息频率、票面利率（有披露时）和含权/续发信息。全量列表接口没有发行金额，必须逐只
调用 `BondDetailInfo`。

因此本轮新增的是被 `.gitignore` 忽略的本地候选市场数据库 `data/lgfv_bond.db`，不写入
`pboc_data.db`，不写入财政部官方政府债务观测，也不把结果命名为官方“城投债余额”。

## 已实现的三层数据

| 层 | 表 | 内容 | 状态 |
|---|---|---|---|
| 候选清单 | `lgfv_bond_inventory` | 债券定义代码、简称、类型、发行人、来源 | 可续跑 |
| 条款 | `lgfv_bond_terms` | 计划/实际发行额、到期日、付息频率、票面利率等 | 可续跑 |
| 推导现金流 | `lgfv_bond_cashflows` | 按条款生成的付息日程和到期还本日程 | `derived_schedule` |
| 官方公告 | `lgfv_bond_notices` | 付息/兑付公告标题、发布日期、附件链接 | `official_notice_metadata` |

实际公告金额只有在正文或附件可提取时才允许写入；扫描 PDF 或未解析附件保持空值，
不以计划金额冒充已付金额。

## 计算口径

- 历史发行总额：逐只 `issueAmnt` 相加，仅表示候选债券历史发行规模。
- 候选存续上限：截至日后仍未到期且有实际发行额的债券 `issueAmnt` 之和。
- 该上限不是当前余额：还没有完整覆盖交易所市场、跨市场去重、回售/提前兑付、分期还本
  和存续期余额快照；所以 API 字段名为 `estimated_current_balance_upper_bound`，状态为
  `market_estimate`。
- 计划付息：`实际发行额 × 票面利率 × 每期月份 / 12 / 100`，仅在票面利率和付息频率
  均有披露时计算；日期仍是“计划/推导”，不是实际已付。
- 到期还本：按实际发行额在披露到期日生成 `scheduled_principal`，没有部分偿还数据时
  不把它当作完整偿还记录。

## 官方公告入口

付息兑付公告通过中国货币网 `clinrAnNotice` 接口按债券类型分页，当前公开查询可回溯到
接口返回的最早日期（本轮默认 2023-08-07）。公告元数据保存 `contentId`、标题、发布日期、
原文页和 PDF 附件链接；公告金额解析是单独的后续层，遇到扫描件会保持缺失。

## 2026-08-07 失败回填修复

全量详情第一次长跑记录了 238 条失败：其中 237 条集中在短期融资券的旧券区间，错误为
`OSError: [Errno 22] Invalid argument`；另 1 条为临时空响应导致的 JSON 解析失败。对失败代码
单条复测均能从同一官方 `BondDetailInfo` 接口返回完整 JSON，因此这些记录不能解释为“无条款”。

已做三项修复：

1. 单条详情对低层 `OSError`、空响应和无效 JSON 增加 1/2/4/8 秒退避重试，默认最多 4 次；
2. `lgfv_bond_terms(snapshot_date,bond_defined_code)` 和清单连接键增加索引，失败/断点候选查询
   实测从长时间扫描降至 0.102 秒；
3. 进程被中断时进度改为 `partial`，避免留下不可解释的 `running` 状态；详情按每批 2,000 条
   独立续跑，减少长事务风险。

当前复核结果：238/238 条失败记录已重试成功，当前 `error_terms=0`；剩余的是尚未处理的
候选条款，不再是这批失败。新增重试与索引单测后，全仓 **454 tests passed**。截至本记录，
全量详情续跑已恢复至 16,990 条成功条款；公告表仍只有先前 230 条 smoke 元数据，尚未开始
公告全量回填。

## 红线与开放问题

这套数据不能回答“全国城投债官方余额”或把城投债并入政府债务。它可以在私有库内形成
“公开债券候选集合 + 发行额 + 透明的存续上限/付息计划 + 公告记录”，但若要升级为更接近
当前余额的市场估计，还需要授权的交易所数据、明确发行人分类规则、跨市场去重和逐笔
存续期偿还快照。
