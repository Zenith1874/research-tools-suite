# 城投债候选债券库存侦察状态（2026-08-05）

## 结论

AKShare 的 `bond_info_cm` 确实可以调用中国货币网的公开债券查询接口，拉取银行间债券的逐只元数据；但它不是一个“全国城投债余额”接口。清单返回债券代码、简称、债券类型和部分发行人等字段，不能直接提供当前存续余额。

因此本轮只建立候选债券库存，不把发行金额当成余额，不写入 `fiscal_debt_observations`，也不改变债务页的官方广义债务口径。

## 接口实测

- 底层列表接口：`https://www.chinamoney.com.cn/ags/ms/cm-u-bond-md/BondMarketInfoList2`
- 查询入口：`https://www.chinamoney.com.cn/chinese/scsjzqxx/`
- 单只详情接口可返回发行人、到期日、计划发行量和实际发行量；“当前存续余额”不是列表字段，单只详情也不能替代跨市场余额快照。
- 接口按债券类型分页，实测每页返回15条；连续长连接偶发停滞，管线改为每页独立请求并保留断点。

## 候选全集规模

候选类型不是官方“城投债”分类，只是可能承载城投主体融资的银行间债券类型：

|---|---:|

| 短期融资券 | 12,023 |
| 中期票据 | 31,003 |
| 集合票据 | 126 |
| 超短期融资券 | 37,935 |

按接口单页15条计算，约5,935页。这个数字是候选债券清单规模，不是城投债余额。

## 本地实现与实测

- `services/lgfv_bond_service.py`：新建独立库存表和逐页可恢复扫描；使用中国货币网公开接口，底层与 AKShare `bond_info_cm` 一致。
- `scripts/update_lgfv_bond_inventory.py`：默认写入被 `.gitignore` 忽略的 `data/lgfv_bond.db`，支持 `--max-pages` smoke test和断点续跑。
- 本地 smoke test：9类各抓1页，共133条；发行人非空107条，覆盖80.45%；当前余额字段0条。
- 断点测试：从第2页继续到第3页，随后单独验证第4—6页；当前独立库库存418条、定义代码去重后仍418条，发行人非空383条（91.63%），无当前余额字段。
- 测试：`tests/test_lgfv_bond_service.py` 3项通过。

## 当前不能回答的字段

`bond_info_cm` 全量清单之后，还缺三层工作：

1. 逐只发行人分类：公开接口没有“城投/LGFV”官方标签；
2. 补充交易所公司债/企业债并跨市场去重；
3. 取得当前存续余额或存续期公告快照，处理提前偿还、回售、续期和分期还本。

在这三层完成前，系统仍然显示城投债余额 `missing`，而不是把清单规模或实际发行量冒充当前余额。
